## 功能需求

4. **闸口节点**：新增「闸口」形式节点 = 必须人工审核才能通过的节点。普通节点允许人工介入但不强制；闸口不人工确认不得推进到下一节点。（验收：闸口未确认时下游节点无法开工/推进；普通节点可直接推进）
5. **星轨标题规范**：不写「产品交付组」这类组织/组名，标题 = 状态 + 任务名称。
6. **左侧星轨列表标准交互**：支持分组、筛选等列表常规操作。
7. **站尺寸自适应**：站内节点很多时，展开后的站尺寸应自适应变化（不能固定尺寸溢出/遮挡）。
8. **右键菜单**：星轨支持多选成组、右键删除；节点支持右键删除等常规操作。可顺带评估「认领/标记完成」入口（配合闸口与协作推进，方案你定）。
9. **默认星轨组改为两个**：
   - ① 需求开发流程组（现有 Agent Team 流程保留）；
   - ② **bug 修复组**（内含一个 bug 修复流程），目标是替代 jira。
   - jira 提 bug 流程（醇青口述，先按此建模）：填 bug 标题、优先级、经办人、详情（文字描述/附件）→ 提交后状态「开放」→ 开发修复后标「已解决」；状态全集：开放/开发中/测试中/重新打开/已解决/已关闭；**每一次状态改动都记录时间 + 改动内容**。
