# 星图 V7 设计决策

日期：2026-09-24  
适用端：`portal-desktop` Electron + React + Vite  
唯一需求基准：`pipeline/v7-requirements.md`

## 1. B1–B3 根因与修法

### B1 点击站后，站内节点被覆盖

根因不是站尺寸计算本身，而是 React Flow 默认的 `elevateNodesOnSelect`：站与节点虽然都是绝对坐标实体，但选中站时 React Flow 会把整个站节点抬到普通节点之上，带背景色的站容器于是覆盖站内节点。应用样式中通用的 `.react-flow__node.selected` 层级还会强化这一行为。

修法：

- 关闭 React Flow 的默认“选中即抬升”；
- 明确固定站、普通节点、选中普通节点的层级分别为 0、2、4；
- 保持 V6 的绝对坐标、站尺寸自适应与拖动站时带动成员节点逻辑不变。

因此反复选择站只改变选择态与详情内容，不再改变站和成员节点之间的遮挡关系；旧数据中的 `stationId` 归属同样走这条渲染路径。

### B2 专注模式页面全白

根因是专注态同时把原生顶层 `#place-sheet` dialog 和它内部的 `#pipeline-view` 都设置为 fixed 全屏。内部 fixed 覆盖面处于带动画、裁剪和顶层语义的 dialog 中，形成两套互相竞争的全屏几何与层叠上下文，React Flow 在切换期间可能拿到无效可用尺寸，最终只剩覆盖面的空白背景。

修法：

- 只让已经处于浏览器 top layer 的 `#place-sheet` 扩展到全视口；
- `#pipeline-view` 保持普通 flex 子项，不再创建第二个 fixed 覆盖面；
- 专注切换只改 class 与侧栏状态，不挂载/卸载 React Flow，原节点、边和 viewport 实例持续存在；
- 常驻功能栏在专注态保留，退出按钮始终可见；Esc 仍调用同一退出函数并恢复进入专注前的左右栏状态。

### B3 左栏折叠后无法展开

根因是 V6 的展开按钮定位在画布内部。侧栏列宽、画布边界和专注覆盖面同时变化时，入口依赖画布定位与层叠关系，无法保证始终处于稳定可点区域。

修法：左右栏入口统一迁到页面常驻功能栏，完全脱离被折叠的侧栏和会改尺寸的画布。折叠列宽仍为 0，画布通过 grid 自动取得释放的空间；按钮用相反方向箭头表达当前的展开/收起动作，左右行为对称。

## 2. B4 客户端头部模式提取

先读取了以下现有实现：

- `desktop/renderer/app/components/navigation.tsx`：`PlaceHeading` 统一提供页面大标题、返回/前进、关闭和功能切换导航；
- `desktop/renderer/app/styles.css`：大标题为 26px Georgia/宋体衬线字，头部左右内边距 28px；
- `desktop/renderer/town/page.tsx`：工具库与卷轴共用 `.town-toolbar`，常驻功能控件使用 12px 字号、12–20px 间距和底部分隔线，搜索与筛选处在内容区顶部。

V7 采用同构层级：

1. 恢复由 `PlaceHeading` 展示的大标题「星图」，不再在星图内部重复放一个小标题；
2. 在大标题下设置固定功能栏，控件顺序为搜索、筛选（状态与分组视图）、左栏、右栏、专注；
3. 功能栏采用 12px 表单控件、28px 水平内边距、12px 主间距和底部分隔线；窄宽度下只换行，不隐藏关键入口；
4. 画布只保留缩放、适配和创建操作，不再重复放专注或侧栏按钮。

## 3. B5 删除“更多”

原“更多”只承载流程版本与状态图例，没有编辑动作。V7 删除按钮和浮层；状态已经在节点卡片、星轨名称和详情核心区直接呈现，流程模型仍由当前星轨的 `workflowId` 决定，没有业务能力丢失。

## 4. B6 详情面板精简取舍

右栏宽度保持 V6 的 300px，不改布局契约。默认区固定围绕四件事组织：

- 这是什么：名称与对象类型；
- 什么状态：节点可直接切换状态，站显示完成进度，星轨显示当前业务状态；
- 谁负责：节点可直接编辑负责人，站说明由站内节点分别负责，星轨显示负责组；
- 下一步动作：节点按当前状态给出推进按钮，站可整理站内节点，星轨可进入专注，批量选择可自动排序或创建站。

以下信息降到折叠的「更多信息」：归属站、人工审核配置、分配对象、说明、证据、拍板人、执行/触发/证据等级、站描述、Bug 元数据与历史、删除动作。字段和原有操作仍可找回，但默认不再占用纵向空间。

## 5. B7 评论数据模型

评论与 V4/V5/V6 主星图状态分开存储，避免为评论升级或重写 `beings:star-map:v4`：

- key：`pipeline_comments_v1:<encodeURIComponent(demandId)>`；使用需求指定前缀，并按星轨隔离同名模板节点，避免不同星轨的 `N01`/`S01` 评论串线；
- value：评论数组；单条结构严格为 `{ id, targetType: 'station' | 'node', targetId, author, content, createdAt }`；
- `author` 当前写入 `board.currentUserId`（默认 `local-user`），为真实协作者身份预留；
- 读取时逐条宽松校验，损坏评论只被忽略，不会阻断主星图加载；
- 发送时立即写入 localStorage，并同步当前详情；V7 不提供修改或删除。

详情中的评论区以 `targetType + targetId` 过滤。已有评论时默认展开并显示作者、时间和完整内容；无评论时只保留紧凑的折叠入口，展开后才出现输入区，不渲染空列表或占位文案。

## 6. 兼容与验证边界

- 主状态键、schemaVersion、V3/V4/V5/V6 迁移与清洗逻辑均不修改；评论使用独立 key，不参与旧数据迁移。
- 不启动 Electron 或任何图形界面。
- 本轮验证只执行根目录 `npm run typecheck`、`npm run build:portal` 和代码自审；交互次数与视觉一致性由 Heart 在真实客户端统一验收。
