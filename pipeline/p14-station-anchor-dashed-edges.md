# P14 站点锚定虚线（2026-09-24 14:59 醇青提议）

## 背景（用户原话）
> 我现在连接的这第一个站为什么显示橙色，照理说是连接上的啊
> 还是设计不对？给每个站的内第一个节点和最后一节点分别再自动加上一个连接此站点的更浅色的一点的虚线？用来表示第一个节点和最后一个节点是跟站点连上的

## 动机
站间紫线（P9）连的是**站框**，站内连线（P10/P11）连的是**节点**。视觉上「上站尾 → 本站首」这段在站框处断开——观者无法一眼读出首/尾节点与站框的从属衔接关系，也间接导致「明明连上了为什么还橙」的误读。虚线把「站框 ↔ 首/尾节点」这段补画出来，整条链路视觉连续。

## 需求
1. 每个站自动生成两条派生边（derived edge，仅渲染层，**不写进 localStorage / demand 数据**）：
   - 站框 → 站内第一个节点
   - 站内最后一个节点 → 站框
2. 样式：浅紫虚线——比站间紫线（#8B5CF6）明显更浅（建议 #8B5CF6 45% 不透明度或 #A78BFA），`stroke-dasharray` 约 `5 4`，线宽 1.5px 左右，**无箭头**（从属语义，非流向语义）。
3. 首/尾判定沿用现有 `orderedStationNodes(stationId)`（站定义 nodeIds 顺序），与其他站内逻辑同源。
4. 单节点站：首=尾，只画一条（去重）。空站：不画。
5. 不可交互：`selectable: false`、`focusable: false`，右键/点击不弹菜单、不进多选、不可删。
6. 站收起（compact）态：隐藏这两条虚线（P10 收起态紫线优先，节点都藏了，虚线悬空会脏）。
7. 锚点：站框侧用站容器 handle（P9 站间边同款）；节点侧用节点朝向站框一侧的 handle。两条虚线与站间紫线的落点错开，避免三条线挤在同一点看不清（具体 handle 位置你定，验收看视觉清晰度）。
8. 专注模式：与其他边同规则（专注态下画布内正常显示）。

## 非目标（别碰）
- P9 站间边、P10 收起态紫线、P11 橙框/紫框判定逻辑一字不动
- localStorage / schema / demand 数据结构不动
- 侧栏、顶栏、折叠按钮（P13 刚验收完）不动

## 自测
- tsc + renderer 构建通过
- 自查：默认 beings-development 流程下 S01-S06 每站两条虚线可见、S01 单节点站不重复、收起站后虚线消失

## 验收（由我在隔离实例 9223 复验）
- 每个有节点的站：首/尾各一条浅紫虚线连到站框
- 虚线样式三要素（更浅、虚线、无箭头）与站间紫线可区分
- 单节点站只一条；空站无
- 不可选中/不可删；收起态隐藏
- P9/P10/P11 回归：站间紫边、三态健康指示、橙框判定全部不变
