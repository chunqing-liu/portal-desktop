### 3. 全屏行为重做
现状（负责人实测）：
- V3 全屏走 Electron IPC `win.setFullScreen`，实测 1266×823 → 1707×960，是**整个应用窗口 OS 级全屏**。
- 醇青要的是**画布区域全屏**：应用内画布铺满内容区（顶栏/侧栏收起或被覆盖），不是 OS 级全屏。
- 外置浏览器打开提示「页面未加载完成」。根因（负责人实测）：页面内嵌 `<iframe src="beings://chat/...">`，beings:// 协议外置浏览器无法加载，iframe 挂起导致页面永远转圈。dev server 本身 http://localhost:5173 返回 200 正常。
- 方案方向（codex 设计）：画布全屏 = 应用内专注模式；外置浏览器 = 剥离/降级 beings:// iframe 或提供纯画布路由。做不稳就按 V3 预案删按钮，不留半残功能。

### 4. 放大后节点卡片遮挡画布
现状：放大后出现的节点卡片挡住原有界面内容。醇青给了两个方向：
- A：卡片折叠向下展开（收起时不挡，展开往下长，不遮挡上方内容）
- B：自适应细节分级（zoom 不同档位显示不同细节程度，节点自身尺寸始终不变）
要求：codex 对比两案给出推荐+理由（B 案「前提是你能设计好」，设计不好就选 A），实现选定方案。

### 5. 「新建星轨」按钮文案改「新建」
现状实测：按钮存在，文案「新建星轨」。

### 6. 连线必须可用，支持自由组合
现状（负责人实测）：
- `onConnect` 有实现（customTransitions 落库），但醇青手动操作没试出来，负责人 CDP 程序化触发也未成功——交互可发现性/可触发性差（handle 太小或拖拽区域不明确）。

- 要求：先读参考仓的画布节点交互（连线手柄样式、拖线交互、节点自由组合），提炼可借鉴模式，再改星图。**参考仓只读，严禁改动 E:\Agentspace\co-design-client 下任何文件。**
